# Mock data (fictional)

Bay Light Day Cruises, Seward is a FICTIONAL TEACHING BUSINESS. Every row here was generated by
`python tools/make_mock_data.py` with a fixed seed, so the files come out the same every time.
The mock replays the 2026 season (May 15 to September 15).

## baylight-bookings-mock.csv (300 bookings)

| Column | Meaning |
|---|---|
| booking_id | Plain ID, no personal data |
| booked_date, trip_date | YYYY-MM-DD |
| departure_time | 9:00 or 14:00 |
| product | The trip booked |
| rate_type | flexible or non_refundable |
| channel | direct, ota or hotel_desk |
| party_size | Guests on the booking |
| addons_count | Add-ons already on the booking |
| price_alert_flag | 1 if the platform shows the guest is watching the price (only some platforms have this) |
| booking_value_usd | Invented for the report's revenue line. Bay Light's fact sheet has no price. |
| status | open |
| booking_note | Free text. It is here on purpose: the adapter drops it, because notes often hold personal details. |

There are no names, emails, phones, addresses or payment data, and the pilot never asks for them.

## baylight-outcomes-mock.csv (300 outcomes, simulated)

| outcome | Meaning | In Number 4? |
|---|---|---|
| kept | Trip went ahead as booked | counted, not an event |
| changed_in_window | Guest changed the booking while free changes were allowed | event |
| cancelled_in_window | Guest cancelled while free cancellation was allowed | event |
| cancelled_late | Guest cancelled inside 48 hours (no refund) | counted, not an event |
| operator_cancelled | The operator cancelled, for example a marine warning | left out |

The chances of each outcome are invented. Treatment bookings got a 25% lower chance of an in-window
event, also invented, so the report has something to show. With 30 eligible bookings, that is noise.
That is the lesson of the power command.

For your own pilot, export the same three columns from your booking platform after the season:
`booking_id, outcome, outcome_date`.
